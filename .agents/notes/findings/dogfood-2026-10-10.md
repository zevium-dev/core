# Dogfood findings — 2026-10-10

> Baseline: `origin/develop` at `eaa7eff`. Browser journeys, curl gateway/MCP calls, Stripe sandbox checkout, Claude Code connection check. Findings describe this baseline, not later fixes.
> Result: **12 new issues: 2 P0, 6 P1, 4 P2. Neither authenticated golden path completed without workarounds.** No product code changed.

## Environment and boundaries

- Separate `dogfood-1` worktree; frozen pnpm install; Node 24.15.0 / pnpm 11.8. Local web `localhost:3000`, gateway `localhost:8787`, isolated anonymous Convex backend `127.0.0.1:3210` / site `3211`. No functions pushed to the shared dev deployment.
- Production `https://www.zevium.dev`: anonymous landing, catalogue, search, detail, docs, mock and discovery only. No production account, payment or metered upstream call.
- Local authentication used the existing Clerk test identity and email test OTP. Created separate publisher and consumer organizations under that same identity; this was **not** a two-identity authorization test.
- All money actions used Stripe sandbox credentials, hosted test Checkout and the test card. A local Stripe listener forwarded test events to the isolated backend. No live charge, refund, Connect onboarding, transfer or payout.
- Browser captures, curl responses and diagnostic scripts are excluded from this commit. No credentials, personal data or private provider IDs are included here.

## Blockers and explicit workarounds

1. Documented `pnpm seed` failed on shared-module resolution; running through `tsx` then failed on the deleted `isPublicCopyAllowed` export (#384). Continued with an ignored scratch copy of the seed script with the obsolete import/check removed. No tracked seed changes.
2. Normal Convex dev startup failed typechecking because key registration references the missing `keySettings.by_owner` index (#385). Continued on the isolated backend with typechecking disabled. The same defect then reproduced through normal key-creation UI: `Index keySettings.by_owner not found.`
3. Local CSP blocked the anonymous backend WebSocket and left the authenticated app at loading workspace (#387). Used a browser-session CDP CSP bypass for subsequent authenticated journeys. Fresh anonymous local mock testing used a separate browser without this bypass.
4. Publishing with stored upstream credentials failed after repeated successful health checks (#389). Removed the harmless test credential, retested and published, then restored the harmless header for gateway injection testing.
5. UI key issuance was blocked by #385. Supplemental gateway tests used Clerk-issued **test** keys and matching `keySettings` fixture rows imported only into isolated Convex. These prove the exercised gateway behavior, not working self-serve key provisioning or UI key lifecycle controls.

## Journeys run

### Visitor — local and production

- Landing communicates prepaid credits, $1 = 10,000 credits, and the publisher 95% share clearly.
- Production had one public listing, **Markdown to HTML**, at 20 credits with a five-call free tier. Lexical search for `markdown` and semantic search for `convert markdown to HTML` both found it; semantic result showed 74% match.
- Production API detail and anonymous mock worked: POST mock returned HTTP 200 with the spec-generated string response. Fresh local anonymous mock also returned successfully without a key.
- Production discovery returned JSON with the public listing, prices, free tier and HTTPS production gateway address. Local discovery returned the new published listing but generated the wrong gateway origin (#392).
- `/llms.txt` returned 404; already tracked by #322. Client-specific installation remains covered by #326.
- At 390 × 844, tested production catalogue/detail had no horizontal overflow. Automated axe 4.12.1 check on the mobile catalogue reported 38 passes and zero violations. This is a page-specific automated result, not an accessibility certification.
- Docs lack a main landmark (#386). The authenticated app also has sidebar landmark and heading-order issues (#397). Browser/network diagnostics exposed the local CSP failure; no claim of comprehensive console-error coverage across every route.

### Publisher — local test organization

- Created organization and project through UI. Pasted an OpenAPI 3.0.3 spec targeting `https://httpbin.org`; later file upload of the same spec also succeeded. Autosave and validation feedback worked.
- Spec contained GET `/get` at 7 credits with an optional `message` query parameter, a GET `/status/200` health endpoint at explicit 0 credits, and GET `/uuid` without a price.
- The unpriced operation warned `Missing x-zevium-cost (defaults to 1 at gateway)` and was listed at 1 credit. This reproduces the existing gap #316, not a new issue. No paid call was made to that operation.
- Stored a harmless custom upstream header; secret entry was write-only. Health check passed with HTTP 200. Publishing repeatedly failed with `Run a new credential-free reachability test before publishing.` (#389).
- After the credential workaround, published version 0.0.1, made it public, and found it in catalogue and discovery. Published content remained unchanged when the draft was subsequently invalidated.
- Configured a webhook to the harmless public echo service. `spec.published` was delivered in one attempt. The publisher's make-public action did not enqueue the documented visibility event (#393).
- Entering `-1` in the inline price field produced correct validation text but disabled the field needed to repair it (#399). Restored the valid draft through the spec editor.
- Analytics and earnings populated after the paid calls. Two calls, 100% success and endpoint gross spend were correct. Analytics rounded net earnings to 13 credits while the earnings ledger showed 13.30 (#398).

### Consumer — local second organization

- New consumer organization began with zero credits; the planned signup credit is already #317.
- Normal key creation failed before copy-once secret reveal (#385). Provider-valid fixture keys allowed the remaining gateway checks without changing product code.
- UI $10 top-up opened Stripe **sandbox** Checkout. Test payment returned to local billing, and the webhook credited exactly 100,000 credits. Payment history showed $10.
- Direct gateway GET `/get?message=paid-direct` returned 200, charged 7 credits and preserved the query. Upstream echoed the harmless publisher header; the consumer Authorization credential was not forwarded.
- One queryless MCP call also succeeded and charged 7 credits. Realtime consumer billing eventually showed **99,986 remaining, 2 calls, 14 credits spent** without a reload. Member/key/API/endpoint breakdowns and both activity rows agreed.
- A separate zero-wallet fixture was rejected with HTTP 402 for both the 7-credit operation and the explicitly free 0-credit health operation. Zero balance blocked execution in both cases.
- A fixture key with a 6-credit monthly cap could not buy the 7-credit call: HTTP 403 `key_cap_exceeded`, including through MCP. No charge recorded for these failures.
- Revoked the zero-wallet key at Clerk; after the key cache TTL, gateway refused it with HTTP 402 and `invalid_api_key`. This is provider-revocation evidence, not proof that the blocked UI key-management journey works.

## Overall impressions

1. **The value proposition is clear.** Prices, prepaid credits and keyless mocks make the public product understandable. The single production listing makes the marketplace feel thin.
2. **Self-serve onboarding is not working on this baseline.** Credentialed publication and key issuance both stop ordinary users. The time-to-first-call promise is unattainable through the tested normal UI path.
3. **The exercised money path is encouraging.** With provisioning workarounds, sandbox Checkout, metering, activity, ledger attribution and the 95/5 split agreed. Zero balance and cap enforcement held.
4. **Agent integration needs more than a reachable MCP endpoint.** Query parameters, actionable payment failures, correct discovery origins and working client config are all part of a usable integration; each caused friction here.
5. **Polish is uneven.** Public search and mocks work; local setup, accessibility landmarks, fractional earnings display and invalid-field recovery still impose avoidable effort. Fix the P0 paths before calling this launch-ready.

## Limits and follow-up

- Retest #385 and #389 through normal UI with no fixtures or credential workaround, then repeat the complete publisher → consumer → MCP journey.
- Separate organizations were tested under one identity. Invitations, cross-user RBAC, key rotation, UI revocation, and copy-once key reveal remain unverified in this run.
- URL-based spec import, destructive lifecycle actions, load/concurrency, refunds/disputes, Connect settlement and real production money were outside this run.
- Automated accessibility checks cover selected pages only. No comprehensive screen-reader or keyboard-only audit.
- Temporary provider fixture keys were revoked, both dogfood browser sessions closed, and the Stripe listener, local web, gateway and Convex servers stopped. Ports 3000, 8787, 3210 and 3211 were closed after cleanup.
- Disposable test organizations, sandbox Checkout history and local backend data remain test artifacts. No production mutation was performed.
