# Codebase audit — shared, tooling, CI, e2e

> Date: 2026-10-10 · Read-only audit
> Scope: `packages/shared/src`, `scripts/`, `e2e/`, `.github/`, root configs, `.agents/skills`
> Method: read code, `git grep` every consumer, ran `public-claims` / `parseSpec` under tsx (Node, dev box), pulled CI timings via `gh run view`.

## TL;DR

- About 13k LOC of tooling/e2e/CI can go today with **zero product behavior change**. Most of it is tooling that checks other tooling, or proof machinery for a payment drill that CI never runs.
- `public-claims.ts` (1,887 LOC) is the worst thing in scope. It is a **real launch bug**, not just bloat: it costs about 40 ms CPU per KB of spec (247 ms for a 4 KB spec, 7.3 s for a 196 KB spec), it runs inside Convex reactive catalogue/search queries (loop up to 240 projects) and on gateway spec cache fills, and it blocks legitimate copy ("HIPAA eligibility check") while letting "Our SOC 2 report is available" through.
- `registry-sync.ts` (1,728 LOC) is the producer half of a protocol with **no receiver**. The gateway has no `/internal/registry/v2/events` route. Every outbox event retries 20× and then dead-letters.
- CI wall time is fine (~2 min `ci:pr`). The cost is maintenance surface, not speed.
- Verdict: **prune tooling hard, rewrite 2 shared modules, keep the rest of shared.** No full rebuild needed for this slice.

## 7. Real bugs (ranked)
