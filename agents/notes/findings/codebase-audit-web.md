# Codebase audit — web

> Date: 2026-10-10 · Read-only audit
> Scope: `apps/web/src/` (215 files, 33,795 LOC excl. `routeTree.gen.ts`; 58 test files = 6,074 LOC), `apps/web` configs (vite, wrangler, `server.ts`, CSP, build scripts).
> Method: `wc -l`, grep sweeps (raw colors, durations, `isLoading`, useState loading flags, `invalidateQueries`, dead exports/modules), full reads of shell/provider/infra files, and three parallel full-read sub-audits (spec editor + project; catalogue + landing + docs; billing/keys/activity/admin). Every bug below was checked against source. "By reading" = traced in code, not reproduced in a browser.

## Verdict up front

The code is **not slop at the hard edges**. It **is** slop in the middle layer. The hard parts are correct, tested and worth keeping: SSRF-safe spec import, the killable YAML worker, sealed key lifecycle and rotation, the CSP nonce boundary, the view-transition adapter, error sanitization and the motion primitives. Rule compliance is clean: zero raw Tailwind colors, zero hardcoded durations, zero `isLoading` outside `useConvexAuth`'s API name. The rot is in:

- hand-rolled pagination that breaks realtime
- effects that copy props into state and clobber user input
- pointless invalidation of Convex queries
- 900–1,500-line god files
- duplicated formatters, tables and dialogs
- a provider topology that remounts the app between public and signed-in routes

**Recommendation: prune + targeted rewrite, not a from-scratch rebuild** (reasoning at the end).

## Architecture / provider / auth complexity

- **SSR for `/app` is dead weight.** The `/app` layout gates `<Outlet/>` on `useEnsureMirror().isReady`. That needs `useConvexAuth().isAuthenticated`, which `ConvexProviderWithClerk` only sets after a client effect. So **SSR of every `/app` page renders the workspace skeleton** (`app.tsx:329-356`). Yet each SSR request does:
  - root `fetchConvexAuth` (Clerk `auth()` + `getToken`) — `__root.tsx:44-59`
  - `/app` `requireAuth` (a second `auth()`) — `app.tsx:283`
  - `/app/projects` `ensureMirrorOnServer` (a third `auth()` + `getToken` + 2 Convex **mutations** from a GET server fn) — `projects/index.tsx:46`, `lib/ensure-mirror.ts`
  - plus loader prefetches in `app/index.tsx:58-70`, `$projectSlug.tsx:91-109`, `spec.tsx:25`

  The only payoff is warm cache after hydration. Fix: `ssr: false` on `/app` (or drop the server branches); delete `ensure-mirror.ts` (113 LOC), `getAuthOrg` (dead), and the SSR token path once public pages stop needing it.

- **Provider topology is custom infra.** Built: `route-providers.tsx` (57), `provider-scope.ts` (10), `authenticated-providers.tsx` (57), separate `ClerkProvider` mounts in `app.tsx:299`, `admin.tsx:324`, `sign-in.$.tsx:22`, `sign-up.$.tsx`, plus lazy-load for catalogue detail. Goal: keep clerk-js off anonymous cold loads. Cost: bug #11, blank boundaries, 6 provider mount points, 150 LOC of tests (`route-providers.test.tsx`). Standard Clerk TanStack Start = one `ClerkProvider` + `ConvexProviderWithClerk` in `__root`. clerk-js loads async and SSR HTML is unaffected. **SIMPLIFY to root providers.**
- **Principal cache** (`principal-cache.ts` 39 + router hash prefix + dehydrate/hydrate + `PrincipalBoundary`). Its intent is real: no cross-org flash on org switch. The mechanism is heavy. Equivalent: key the app subtree on `orgId` and call `queryClient.clear()` when the principal changes. SSR already gets a fresh QueryClient per request (`router.tsx:52-69`). **SIMPLIFY** (~80 LOC + tests).
- `lib/clerk-client.ts` (74) reads `window.Clerk` with fallback, for sync client `beforeLoad`. Acceptable, but with root `ClerkProvider` use the router-context auth pattern from `clerk-tanstack-patterns` instead.
- **View transitions**: `lib/vt.ts` (126) monkeypatches `router.startViewTransition` (private API; router pinned to exactly `1.170.41`). `lib/view-transition.ts` (52) encodes the morph target into VT type strings. Works, is tested (`vt.test.ts` 264), and does what TanStack can't today. **KEEP**, but treat it as an upgrade risk. Gate it on the router version in CI.
- **CSP / worker**: `security-headers.ts` (148) is good. Per-request nonce + `strict-dynamic`, Clerk FAPI origin derived from the publishable key with hostname validation, `no-store` on auth surfaces, streamed body. `server.ts` asset allowlist is fine but incomplete (bug #12). `run_worker_first: true` runs every asset through the worker; justified for the header boundary, costs a worker invocation per asset. **KEEP.** `scripts/test-csrf-runtime.mjs` + runner (352) builds the real worker and asserts headers/CSRF. Heavy but the only real integration test of the built artifact. **KEEP.**
- `scripts/build.mjs:49-56` deletes `favicon.ico`, `logo192.png`, `logo512.png` from `dist`, calling them "retired assets lingering in older checkouts". They are **tracked** in `public/`. Delete the files and the loop.
- Double theme init: `__root.tsx:61` inline `themeInitScript` **and** next-themes' own injected script. Keep one.
- **Role gating has two models.** Client `isPrivilegedOrgRole(membership.role)` (dashboard, projects, earnings, keys, org) vs server-projected capabilities, runtime-validated (`lib/org-capabilities.ts` `parseOrgCapabilityProjection`, billing, activity). Pick one: `projectOrgCapabilities(role)` from shared is pure; use it client-side, and let server authz stay authoritative.

Meanwhile `styles.css:332-358` **already retimes the same components by `data-slot`**: two mechanisms, and the CSS one is the right one. Revert `ui/*` to stock and keep the CSS layer. Stock `table.tsx` is missing; add it.
- Design doc drift (code wins, fix the doc): no `layoutId` nav pill or tab underline exists (grep `layoutId` = 0); no `<Pop>` primitive; `.skeleton-crossfade` (`styles.css:487`) unused; `styles.css:6-7` "Hallmark · macrostructure … pre-emit critique" comments are generator residue. Delete.
- Custom tokens `--success`, `--warning`, `--syntax-*` (`styles.css:44-60,98-114`) contradict "no custom palette". Small and used (7 uses + highlighter). Accept and document, or drop.
- View-transition morph: present for project cards, catalogue cards, home teasers (`data-transition-surface`). Compliant.
- Reduced motion: global kill switch `styles.css:414-450`; every `components/motion/*` gates on `useReducedMotion`/`useHydratedReducedMotion`; `LazyMotion strict` with `m.` only (`router.tsx:113`). Compliant.
- Mutations: one `mutateAsync` (`spec-workspace.tsx:271`), justified for save-then-leave. Compliant.

## (2) Prune vs rebuild

**Prune + rewrite four hotspots. Do not rebuild from scratch.**

- About 6k LOC is hard-won, tested edge handling that a rebuild would re-derive and likely get wrong the first time: SSRF import, YAML worker, key sealing/rotation, CSP, VT adapter, gateway error allowlist, Stripe status mapping. It is already correct.
- Design-rule compliance is already clean (0 raw colors, 0 hardcoded durations, motion fully tokenized, reduced-motion global + per-component). A rebuild buys nothing there.
- The defects are **systemic patterns, not a bad foundation**: hand pagination (6 sites), props→state effects (6 sites), Convex invalidations (15 sites), local formatters (47), god files (9). Each pattern has a mechanical fix (`usePaginatedQuery`, derived state / `key` remount, delete, `lib/format.ts`, split) that can be applied file by file with tests green.
- **Rewrite** (behind the same route paths): `spec-workspace.tsx` (state → one `useSpecDraft` reducer hook, conflict-checked save with base hash), `project-settings-panel.tsx` (split into 5 cards, no prop mirroring), `settings/activity.tsx` (`usePaginatedQuery`, shadcn Table), and the provider topology (root Clerk + Convex, `/app` `ssr:false`).
- Order:
  1. zero-risk deletions (section 1)
  2. bugs #1-#4, #6, #7
  3. providers + `/app` SSR
  4. `lib/format.ts` + shadcn `Table` + `DataTable`, `CopyButton`, `VisibilityDialog`, `StatusBadge`
  5. the four rewrites
  6. catalogue single tree
- A full rebuild is only justified if the product shape changes (e.g. dropping the publisher console for the agent-first P0 bet). Even then, carry over the "must survive" list verbatim.
