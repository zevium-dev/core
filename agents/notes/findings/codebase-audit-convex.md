# Codebase audit — convex

> Date: 2026-10-10 · Read-only audit
> Scope: `convex/` minus `_generated`. Method: `wc -l`, export→caller map (refs from `apps/web/src`, `apps/gateway/src`, `scripts/`, `e2e/`, `.github/`, internal `internal.*` refs, crons, http routes), table→file map, index→`withIndex` map, targeted reads. `pnpm test:convex` run: 41 files / 505 tests green in 21.5s. Green tests do not mean live code (see "tests test dead copies" below).
> Bug line numbers were spot-checked against source for: projects replace, registerOwnedKey, org webhook archive gap, earnings cap, recordUsage stale rejection, release batch, write budget, registry dispatch. The others come from a close read and are not reproduced.

## Headline

- **Size.** 53.8k LOC: 33.4k source + 20.4k tests. 86 tables, 240 indexes, 366 `v.optional` fields in `schema.ts`, 71 legacy/migration/optional-first comments in the schema.
- **Dead weight.** About 13k LOC can be deleted on a fresh deployment with zero product-behaviour loss. A further ~9k is overbuilt machinery (funding lots, Connect HMAC correlation, registry v2 producer, dual crypto envelopes) that a launch-sized design replaces with ~2.5k.
- **Registry v2 producer is write-only theatre.** Every org/key/route/publish mutation writes immutable event rows (full spec up to 393 KB plus re-encrypted publisher credentials) and schedules delivery to `/internal/registry/v2/events`. The gateway has no such route; it only handles `/internal/registry/v1/` (`apps/gateway/src/index.ts:311`). Production sets neither `GATEWAY_REGISTRY_SYNC_BASE_URL` nor `GATEWAY_REGISTRY_SYNC_HMAC_SECRET` (`.github/workflows/deploy-production.yml:41-42`). So every event fails, retries 20× with up to 15-minute backoff (`packages/shared/src/registry-sync.ts:27-28`), then dead-letters. The gateway actually reads Convex through `/gateway-spec`, `/wallet-grants`, `/ingest-usage`, `catalogue:listPublic` and `specs:getPublishedForGateway`.
- **Migration fences on a database that never had v1 data.** Finance migration: `financeMigration.ts` (4493 LOC) plus the `assertFinanceMigrationAllowsRuntime` gate at ~42 call sites across 9 files. The gate is a no-op on a fresh deploy (it only throws if a job row exists). But one failed `financeMigration.start` (public admin mutation) fences the gateway wallet checkpoint, `recordUsage`, signup, project create and every Stripe webhook until a rerun verifies.
- **Recommendation: rebuild the Convex layer on a fresh deployment**, contract-first. Keep the ~85 public function names the web app and gateway call. Port the ~4-5k LOC of genuinely good code listed in "Must survive". Do phase-0 deletion first either way (one day, zero risk).

## Schema findings

- **Count.** 86 tables. A launch product needs ~24 (target below).
- **Unused indexes.** At least 34 index names in `schema.ts` are never referenced outside the schema. This is a lower bound; shared names like `by_org` hide more. Examples: `by_auto_revoke*`, `by_customer`, `by_expiry`, `by_family`, `by_hidden_sort`, `by_kind_shard`, `by_org_owner_key_at`, `by_org_owner_project_at`, `by_org_owner_project_key_at`, `by_org_project_key_at`, `by_org_project_settlement`, `by_payment_publisher`, `by_report_count_sort`, `by_request_fingerprint`, `by_snapshot*`, `by_status_lease`, `by_updated`.
- **`usageEvents`.** This is the hot write table. It has 17 indexes, at least 5 unused (`schema.ts:653-708`), and 25 optional fields ("missing means legacy/unverified"). Every index is write amplification on every metered call.
- **Optional-first fields that fail closed at runtime (cannot exist on a fresh deploy):**
  - `wallets.debtCredits`
  - `walletFundingStates.migration*`
  - `payments.financeMigration*`, `refunded*`, `walletReversedCredits`, `disputedCredits`
  - `publisherBalances.migration*`
  - `paymentExposures.sourceAmountExact`, `migrationBackfilled`
  - `publisherEarnings.*Atoms`, `released*`, `clawedBack*`
  - `publishReadiness.serverOrigin`, `credentialFingerprint`
  - `keySettings.ownerUserId`, `rotationRequiredAt`
  - `organizations.publicHandle`, `unreadNotificationCount*`
  - `qualityIncidents.restoreVisibility`
  - `registryRollouts` provenance
  - On a fresh deployment every one becomes required or is removed.
- **Tables deletable with zero loss (21):**
  - Finance migration: `financialMigrationJobs`, `financialMigrationAudits`, `paymentFundingLots`, `paymentFundingAllocations`
  - Security rollout: `securityRolloutState`, `securityRolloutAudits`
  - Registry rollout: `registryRollouts`, `registryRolloutSourcePreimages`, `registryRolloutEventReceipts`
  - Registry producer: `registryStreams`, `registryOutbox` (after the two rewires)
  - Unreferenced: `registryManifestSnapshots`, `registryManifestItems`, `keyLifecycleOperations`, `registrySyncStreams`, `registrySyncOutbox`
  - Duplicate limiter: `specImportRateLeases`
  - Deploy ceremony: `deploymentReceipts`, `releaseProbeClaims`, `releaseProbeGates`
  - No writer: `listingSubscriptionAggregates` (and `listingSubscriptions`)
- **Hot documents that violate the CLAUDE.md Convex rules:**
  - `publisherBalances` is patched on every paid settlement from every consumer (`wallets.ts:1297-1305`).
  - `securityRolloutState` singleton.
  - `specImportGlobalLimits` singleton.
  - `organizations.unreadNotificationCount` is patched per notification on the doc every org query reads (`lib/notifications.ts:35`).
  - There is no `convex.config.ts`, so the mandated sharded rate-limiter component is used nowhere.

## Must survive a rebuild

- **Wallet ledger:** `wallets.ts` `appendWalletEntry` (144-218). refId idempotency, immutable-fact replay check, monotonic `sequence` + `balanceAfter`, refuses a negative balance. Also the `getGatewayWallet` checkpoint contract consumed by the wallet DO.
- **`recordUsage` contract:** per-ref `applied`/`already_applied`/`rejected{retryable}` outcomes; one consumer org per batch; ownership of project, version and publisher re-derived server-side; `validSettlementBoundary`/`validSettlementOutcome`; `settlementIdentityFingerprint`.
- **`accounting.ts`:** integer atoms, `publisherEarningSplit`, cents conversion, sub-cent remainder carry.
- **Stripe ingestion:** raw-body signature verification; receipt + scheduled processor in one transaction (`billing.ts:557-631`); lease-token claim with stale-completion rejection (689-805); backoff, terminal states and cron lease recovery; re-fetching the canonical object from Stripe instead of trusting the payload (1724-1924); business idempotency keys (`stripe:payment_intent:*`, `stripe:refund:*`); server-owned `checkoutIntents` verified against session amount, currency, customer, price and quantity (1627-1680); Stripe `idempotencyKey` on customer and session create.
- **Publisher ledger:** `appendPublisherSettlementEntry` (`publisherLedger.ts:165-274`), risk-hold `availableAt` + `releasePublisherEarning`, publisher debt via negative available balance (consumers never carry debt). Transfer idempotency key `publisher-transfer:{org}:{seq+1}` with allocation in the same transaction (`payouts.ts:1960,2053`). Connect account projection + `refreshConnectedAccount` (1337-1422). One-account-one-org `connectedAccountClaims`.
- **Tenancy:** org taken from the signed JWT `org_id`, never the URL (`lib/auth.ts:146-170`). Missing and cross-org rows return the same error, so nothing can be enumerated. `requireAdmin` env allowlist.
- **Clerk mirror:** Svix receipt dedupe, `lastClerkEventAt` stale rejection, delete tombstones beating late creates.
- **Outbound HTTP safety:** `lib/webhookTransport.ts` (DNS-pinned HTTPS, every answer checked, same-origin redirects, bounded time/bytes). Keep one copy, used for webhooks, probes and readiness.
- **Webhook delivery:** lease + self-scheduled recovery, stable delivery id, previous-secret grace window, reveal-once secrets.
- **Lifecycle:** permanent public-route tombstones (handle + slug reserved forever), retired routes resolving to 410, mandatory 7-day sunset, bounded self-rescheduling cleanup pages.
- **Quality:** credential-free reachability probe kept separate from gateway success rate; 3-of-5 suspend / 3-pass recover.
- **Spec import limiter shape** (`specImportLimits.ts` lease/renew/release), minus the global singleton.

## (2) Recommendation: rebuild the Convex layer from scratch, contract-first

- **Why not prune in place.**
  - The problem is the shapes, not just the files. 86 tables, 240 indexes, 366 optional fields.
  - The funding-lot lineage, dual crypto envelopes, atoms-on-every-row, per-call earning rows plus a hot publisher-balance doc, and HMAC-correlated transfers are woven through every money mutation. ~42 fence call sites and ~50 legacy branches touch the paths you would keep.
  - Pruning keeps the schema and the hot-doc design, and every step needs re-proving the existing 505 tests, ~30% of which test dead or slop paths.
  - Data is disposable and a fresh deployment is allowed, so migration cost is zero.
- **Why not a blank page.**
  - The public contract is small and known. The web app calls ~85 functions. The gateway uses 3 http routes (`/ingest-usage`, `/wallet-grants`, `/gateway-spec`) + `catalogue:listPublic` + `specs:getPublishedForGateway` (+ `wallets:recordUsage` fallback). The Stripe/Clerk webhook routes are fixed by provider config.
  - The good code (~4-5k LOC, listed above) is correct and tested; port it verbatim.
- **Order.**
  1. Phase-0 delete the ~13k zero-loss LOC in place (fast; shrinks what must be read).
  2. Write the new schema (~24 tables).
  3. Port the keepers.
  4. Re-implement the money core at ~2k LOC: ledger + simple lots + Stripe + 95/5 + Connect.
  5. Re-implement the rest by module against the same function names, porting product tests and dropping slop tests.
  6. Fix B1-B16 in the new code.
- **Non-finance modules** (projects, specs, catalogue, quality, reviews, webhooks) are closer to right. They can be ported with fixes and table cuts rather than redesigned.
