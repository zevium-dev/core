# Zevium CLI

Single self-contained Node.js ESM script. Requires Node.js **22.12.0 or newer**
(chosen to support Node 22 LTS). No runtime packages or TypeScript runner.

```bash
curl -fsSLo zevium https://zevium.dev/cli/zevium.mjs && chmod +x zevium
./zevium --help
./zevium acme pets
./zevium acme pets getpet_1 --help
# Set ZEVIUM_API_KEY in your environment before execution.
./zevium acme pets getpet_1 --path-id pet-123
```

Move the file onto `PATH` to use `zevium` from any directory. On Windows, save it
as `zevium.mjs` and run `node zevium.mjs --help`. Re-download to update. The stable
path is generated by each web build; it becomes available when the owner deploys
that build. `@zevium/cli` is prepared for npm publication but has not been published.

Command names and flags come from the listing's generated docs; names above are
illustrative. `ZEVIUM_GATEWAY_URL` defaults to `https://gateway.zevium.dev` and
accepts HTTPS origins or HTTP loopback for local development. API keys stay in the
environment, never command flags. Redirects fail rather than forwarding credentials.

Docs/help load `get_api_docs`. Execution sends one `call_api` request to the same
MCP endpoint with the key in its Authorization header. Gateway authentication,
credit reservation, settlement, rate limits, and refunds apply unchanged. The CLI
never reads publisher server URLs and never retries execution automatically.

String flags take literal strings; numeric, boolean, array, and body flags take
JSON. Required flags, duplicate/unknown flags, and JSON syntax are checked locally.
Schema constraints are documented for the caller; upstream validation remains
responsible for payload semantics. Defaults are never injected. Unsupported
operations appear in docs with diagnostic codes and have no generated command.

## Contract compatibility

`GENERATOR_VERSION` is a positive integer **wire-format major**, currently `1`,
independent of the CLI package version and listing version. The CLI explicitly
supports major `1`; it does not automatically follow the shared producer constant.
Additive optional fields can retain major 1 and are ignored by older clients.
Changes to required fields, flag encoding, or call-binding semantics require a
new major and an explicit client compatibility review. Unsupported numeric majors fail before execution with an upgrade message.
Unavailable generation reports its reason and points to listing Markdown; malformed
contracts report "invalid contract". A new major requires a compatible CLI
release before the gateway starts producing it.

Docs identify the immutable published version used for generation. Gateway routes
execute the currently published version, so this entry does not promise version
pinning across publication changes. Requests and streamed responses are capped at
1 MiB; each request times out after 15 seconds.

## Development and release

```bash
pnpm --filter @zevium/cli build
node packages/cli/dist/zevium.mjs --help
pnpm --filter @zevium/cli zevium --help
pnpm --filter @zevium/cli test
```

The dev command rebuilds before running. esbuild bundles shared code and zod into
`dist/zevium.mjs`, writes the Node shebang/runtime guard, and sets mode 0755. Web
builds independently bundle to `apps/web/public/cli/zevium.mjs`; no workspace bin
link or Turbo ordering is needed. Tests build their own scratch artifact, copy it
into an isolated directory, and block external module resolution while exercising
version guards and HTTP docs/calls. All outputs are gitignored. Bundles are minified
and omit legal/path comments.

Owner-only release steps, package inspection, and rollout order live in the
[agent-surface feature note](../../.agents/notes/features/agent-surface.md#cli-distribution-451).
No automatic registry publication or deployment is configured.

Listing-scoped MCP registration is tracked in #110. Generated SDKs remain #350.
